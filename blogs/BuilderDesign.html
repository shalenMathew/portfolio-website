A Quick Guide into Builder Design Pattern in Android

This quick guide to the Builder Design Pattern is perfect whether you’re looking for a quick revision or aiming to grasp the concept from scratch!

The Builder Pattern is a creational design pattern used to construct complex objects step by step. It’s especially useful when an object has many optional fields or when you want to make object creation more readable and manageable.

If a class has many parameters, instead of adding all of them to the constructor and creating a telescoping constructor, the Builder Pattern provides a better approach by allowing you to add or separate optional parameters seamlessly.

Let’s understand this with a clear example using a Person class. In this class, there are fields like firstName, lastName, middleName, age, phoneNo, and address. Among these, firstName, lastName, and age are the only mandatory fields.

The Problem: Without the Builder Pattern

Without the builder pattern, your implementation will look something like this with telescoping constructors:

class Person(val firstName: String, val lastName: String, val age: Int) {
    // Telescoping constructor for different combinations of parameters
    constructor(firstName: String, lastName: String, age: Int, middleName: String) : this(firstName, lastName, age)
    constructor(firstName: String, lastName: String, age: Int, middleName: String, phoneNo: String) : this(firstName, lastName, age, middleName)
    constructor(firstName: String, lastName: String, age: Int, middleName: String, phoneNo: String, address: String) : this(firstName, lastName, age, middleName, phoneNo)
}

fun main() {
    val person1 = Person("John", "Doe", 30) // Only mandatory fields
    val person2 = Person("Alice", "Smith", 25, "Marie") // Mandatory + middle name
    val person3 = Person("Bob", "Johnson", 40, "David", "123-456-7890") // Mandatory + middle name + phone number
    val person4 = Person("Charlie", "Brown", 35, "Robert", "987-654-3210", "1234 Elm St") // All fields
}

A Better Approach: Implementing the Builder Pattern

Here is how we can structure and build this class using the Builder Pattern cleanly:

data class Person(
    val name: String?,
    val lastName: String?,
    val age: Int?,
    val middleName: String? = null,
    val phoneNo: Int? = null,
    val address: String? = null
) {
    class PersonBuilder(val name: String, val lastName: String, val age: Int) {
        var middleName: String? = null
        var phoneNo: Int? = null
        var address: String? = null
        
        fun middleName(middleName: String?) = apply {
            this.middleName = middleName
        }
        fun phoneNo(phoneNo: Int?) = apply {
            this.phoneNo = phoneNo
        }
        fun address(address: String?) = apply {
            this.address = address
        }
        fun build(): Person {
            return Person(name, lastName, age, middleName, phoneNo, address)
        }
    }
}

fun main() {
    // Usage of Builder Pattern
    val p1 = Person.PersonBuilder(name = "Shalen", lastName = "Mathew", age = 22)
        .phoneNo(911)
        .address("Bangalore")
        .build()
}

Let's understand what’s going on in the code:

The Person class has fields like name, lastName, age, middleName, phoneNo, and address. Some of these fields are optional (like middleName, phoneNo, and address).

Inside the Person class, there's a nested PersonBuilder class. This class helps you build a Person object step-by-step. The mandatory fields are defined explicitly in the constructor of the PersonBuilder class.

How It Works:

  • You create a PersonBuilder instance by passing the required fields (name, lastName, age).
  • Then, you can optionally add the optional fields using chainable setter methods like .middleName(), .phoneNo(), and .address().
  • Each setter method uses Kotlin's apply scope function to set the value and return the builder instance itself. This allows for clean method chaining.
  • Finally, you call .build() to instantiate and return the Person object populated with all the configured values.

The Kotlin-Way: An Optimized Alternative

While the above code follows a traditional, Java-style implementation, Kotlin provides a much more optimized way to achieve this setup.

In Kotlin, we can leverage a data class to achieve a builder-like effect simply by defining default values for parameters, making them natively optional. This eliminates the need for an explicit, separate builder class entirely while fully maintaining flexibility in object creation.

data class Person(
    val name: String,
    val lastName: String,
    val age: Int,
    val middleName: String? = null,
    val phoneNo: Int? = null,
    val address: String? = null
)

fun main() {
    // Using named arguments for the constructor
    val person = Person(
        name = "Shalen", 
        lastName = "Mathew", 
        age = 22, 
        phoneNo = 911, 
        address = "Bangalore"
    )
    
    println(person)
}

Explanation:

  • The data class Person has both required parameters (name, lastName, age) and optional parameters (middleName, phoneNo, address).
  • The optional parameters are initialized with default values (null in this case), meaning you can safely omit them when creating a Person object.
